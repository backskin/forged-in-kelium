# Критика В — «проверяется движком» (к каталогу, черновик 1, 30.09.2026)

Все пути от `engine/src/main/java/kelium/`. Код не менялся. Карт и синергий не
предлагаю — только что движок видит, что нет, и где слово каталога двусмысленно.

Обозначения: **ЕСТЬ** — проверяется сегодня; **ДЁШЕВО** — данные в состоянии уже
есть, нужен предикат/хелпер; **НОВЫЕ ДАННЫЕ** — надо писать в состояние или журнал.

## 0. Главное

1. **Три разных движка соседства по ячейкам**, и они расходятся:
   - `engine/Shapes.java:130` — соседство через `sidesFacing`, войска по
     `СекторыВойск` (выбранный или выведенный сектор), авиация — только своя.
   - `engine/CellGraph.java:57-86` — войско без записи в `sideOwner` считается
     стоящим на **всех свободных** ячейках гекса (у наземных войск записи нет
     никогда, `engine/СекторыВойск.java:17-20`) → связность завышена; авиация
     связывает гекс **чья угодно** (`CellGraph.java:37-40`).
   - `engine/Figures.java:99-160` — гексовая фигура, но без ячеек.
   До ячеечных фигур нужно оставить один граф ячеек (скорее Shapes), иначе одна
   и та же раскладка будет «фигурой» для одной карты и не будет для другой.
2. **Журнал хода — главное узкое место раздела F.** Событие `combat_hit`
   содержит всё нужное (кем, какой строкой, с какого гекса) —
   `engine/CombatResolver.java:1275-1280`, — но предикаты читают не события, а
   `TurnJournal`, где запись об убитом (`core/TurnJournal.java:530-532`,
   `Убитый`) не знает ни рода атакующего, ни строки атаки, ни гекса выстрела.
3. **Сектор войска хранится только если его выбрали** (`core/UnitToken.java:49-50`
   `sideMask/sidesHex`); иначе выводится эвристикой «к своим»
   (`engine/СекторыВойск.java:36-39`). Для ячеечной фигуры хватает, но бот
   ставит «как держал бы линию» — движок может засчитать фигуру, которую живой
   игрок не выстроил бы.

## 2. Ориентация здания и сектор войска — хватит ли для ячеек

- **Здание:** ориентации отдельным полем нет. Здание = набор занятых сторон
  гекса `Hex.sideOwner[i]=uid` (`core/Hex.java:23-24`); каждая занятая сторона и
  есть стенка, обращённая к `neighborBySide[i]` (`core/Hex.java:22`, `:285-293`).
  Выбор разворота при стройке — `build_facing` (`engine/Actions.java:1760-1784`).
  Противоположная сторона соседа — всегда `(i+3)%6` (`core/Field.java:44-56`),
  поэтому «стенка к стенке» проверяется однозначно (`Chains.java:36-56`).
  **Хватает.** Край поля: `neighborBySide[i]==null` — стенка «смотрит в никуда»;
  засчитывать ли её в «стенка обращена к …» — решить.
- **Нейтрал:** стенки из углов (`core/Hex.java:72-95`); без углов стенок нет.
- **Наземное войско:** `sideMask` + `sidesHex` (`core/UnitToken.java:49-77`),
  действует только на своём гексе; при заходе на гекс ставится
  `СекторыВойск.поставить` (`engine/СекторыВойск.java:280`; вызовы —
  `Actions.java:1112,1145,2859,3062`, `Effects.java`, `GameEngine.java:1429`).
  Раскладка без выбора выводится (`СекторыВойск.java:65`). Живой игрок сектор
  выбирает, бот — эвристикой. **Хватает**, но: (а) войска в `sideOwner` не пишутся,
  поэтому любой код, читающий только `sideOwner` (CellGraph), их не видит;
  (б) нужен запрет «пересесть на другой сектор, не сходя с гекса», иначе
  ячеечная фигура собирается бесплатно — сейчас это держится только тем, что
  выбор даётся при входе.
- **Авиация:** узел −1, соседствует со всеми наземными ячейками своего гекса
  (`Shapes.java:137-139`); за гекс не тянется (`:148-150`).
- **Гарнизон:** ячейки не занимает (`СекторыВойск.java:71-72`) — в ячеечную фигуру
  не попадает. Если каталог хочет «пехоту в гарнизоне» клеткой фигуры, это
  отдельная метка клетки, а не ячейка.
