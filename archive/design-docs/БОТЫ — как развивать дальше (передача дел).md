# Боты «Кристаллов Раздора» — как развивать дальше

Написано 14.08.2026 на случай, когда меня рядом не будет. Здесь всё, что нужно,
чтобы продолжать работу над ботами самому или с другим помощником: как система
устроена, чем её запускать, как читать числа, на какие грабли я уже наступил, и
что делать с идеей «настоящих нейросетей».

Читается сверху вниз. Ничего из написанного не требует ни интернета, ни оплаты,
ни меня — всё считается у вас на машине.

---

## 1. Главное, что нужно понять про ботов

Бот — это **не** одна программа. Это три слоя, и они отвечают за разное. Путать
их — источник почти всех неверных выводов о «глупых ботах».

### Слой 1. Точки выбора

Движок сам не решает. Дойдя до места, где нужно решение, он спрашивает бота:
«вот список вариантов, какой?». Это `Agent.choose(состояние, варианты, повод)`,
где повод — это `kind`: какое действие взять, куда пойти, кого ударить, что
купить. Живой человек в проигрывателе подключается ровно сюда же.

Значит: **бот не может сделать того, чего движок не предложил.** Если бот не
строит авиабазу — сначала проверьте, попадает ли авиабаза в список вариантов.
Так уже было: карта арсенала висела в меню и не выбиралась ни разу, потому что
оценщик про неё не знал.

### Слой 2. Веса (геном)

Каждый вариант получает оценку, оценка складывается из примерно тридцати весов:
насколько ценен келемий, насколько — убийство, насколько — шаг по науке. Набор
весов и есть **геном**. Он лежит обычным JSON-файлом:

```
simulator/data/genomes/strategic_3p.json
simulator/data/genomes/strategic_4p.json
```

Внутри — по одному геному на характер (`hawk`, `dove`, `balanced`, `opportunist`,
`explorer`, `chaos`, `warlord`). **Это и есть «файл модели»** — просто маленький
и читаемый глазами. Его можно открыть блокнотом, поправить число и увидеть, как
изменилась игра. С нейросетью так не выйдет.

### Слой 3. Просчёт вперёд

Самый сильный слой. Бот берёт несколько лучших по весам вариантов, доигрывает с
каждого несколько копий партии до конца (или до горизонта) и выбирает тот, после
которого дела идут лучше. Это `SearchAgent` + `Lookahead`.

**Измерено: просчёт даёт 69% перевеса по очкам против того же бота без
просчёта.** Настройка весов такого прироста не даёт и близко. Если хочется
«умнее» — это первое место, куда смотреть, а не веса и не нейросеть.

Включается настройкой запуска: `-Dkelium.bots=просчёт`. По умолчанию выключен,
потому что балансовые стенды гоняют десятки тысяч партий и просчёт удорожает их
в разы.

## 2. Что чем запускать

Всё запускается из папки `java-sim`. **С 14.08.2026 три модуля** (заказ
дизайнера «чётко разделить движок / ботов / GUI»), каждый со своим
`target/classes`: `engine` (незыблемое ядро, правила, контент, сам движок —
ничего про ботов и GUI не знает), `bots` (агенты + все консольные пробники,
голый пакет `kelium`), `gui` (окна, Swing). Зависимость строго в одну сторону:
engine ← bots ← gui.

Путь к сторонним библиотекам (снова после каждой правки зависимостей) собран в
`deps.txt` в корне `java-sim` (было `cp.txt` до разделения):

```bash
CP="engine/target/classes;bots/target/classes;gui/target/classes;$(cat deps.txt)"
```

Точка с запятой — это Windows. В Git Bash работает, но **русские пути в Git Bash
использовать нельзя** — он их молча теряет, так уже пропали шесть ваших раскладок.
Для всего, что двигает или удаляет файлы с русскими именами, — только PowerShell.

### Пересобрать

```bash
mvn -q -o compile
```

Из корня собирает все три модуля по реактору в правильном порядке. Собрать
только один модуль (например, при параллельной работе над GUI):

```bash
mvn -q -o -pl bots -am compile
```

`-am` («also-make») обязателен, если модуль от чего-то зависит — иначе Maven
не пересоберёт `engine` сам. Собрать один файл мимо Maven:

```bash
javac -encoding UTF-8 -cp "$CP" -d bots/target/classes bots/src/main/java/kelium/ИМЯ.java
```

Путь `target/classes` теперь называет МОДУЛЬ, где лежит файл (`engine/`, `bots/`
или `gui/`) — не забывать префикс, иначе класс скомпилируется, но не туда.

### Обучение

```bash
java -cp "$CP" kelium.agents.SelfPlayTrainer 200000 24 6
```

Три числа: партий на характер, размер популяции, партий на геном. Миллион партий
на всех считается около 40 минут.

**Обязательно перед большим обучением** — сложить текущие геномы в архив, чтобы
было к чему вернуться:

```powershell
Copy-Item -Recurse "simulator\data\genomes" "simulator\data\archive-ГГГГ-ММ-ДД"
```

### Раннер — всё то же самое мышкой, без командной строки

Это главный ответ на вопрос «а можно ли без разработчика». **Можно.** Программа
`kelium.gui.RunnerGui` (в сборке — «Прогон ботов») делает и замеры, и обучение:

* **выпадающий список «Режим»** — десять режимов замеров: прогон партий, балансовый
  зонд, оценка заданий, характеры ботов, лига, атлас стратегий, разбор по
  признакам, **составы ботов**, **карты рынка по одной**, **карты заданий по
  одной**. Последние три подключены 14.08.2026 — до этого они были только из
  командной строки, то есть недоступны без меня;
* **список «Правила»** — каким сводом играть. Так и сравнивают две версии правил:
  прогнали режим «Составы» на 1.7.1, потом на 1.7.2, сравнили два отчёта;
* **Инструменты → Обучить ВСЕ характеры (самоигра)** — то самое обучение. Оно
  **продолжает с места, где остановилось**: начальная популяция берётся из
  чемпионов на диске, а не с нуля. Значит обучение можно копить месяцами, запуская
  когда удобно;
* **Инструменты → Обучить геном стратега (эволюция)** — обучение одной линии;
* **Инструменты → Проверить сборку (тесты)** — прогнать все тесты и убедиться, что
  ничего не сломано;
* **Инструменты → Папки с раскладками и память ботов** — подключить папку с новыми
  полями и выбрать, откуда читаются геномы.

Окно остаётся отзывчивым, есть кнопка «Остановить», и по готовности —
«Открыть отчёт». Отчёты кладутся в `java-sim/reports/balance/`.

Командная строка нужна только для того, чего в раннере нет, и для очень длинных
обучений, которые удобнее оставить на ночь.

### Замеры из командной строки (обучения не происходит, веса заморожены)

```bash
java -cp "$CP" kelium.MatchLab 1.7.1 4 200      # составы: кто с кем за столом
java -cp "$CP" kelium.CardLab рынок 4 200       # каждая карта рынка по отдельности
java -cp "$CP" kelium.CardLab задания 4 200     # каждое задание по отдельности
java -cp "$CP" kelium.agents.Arena              # лига: кто кого бьёт
```

Отчёты кладутся в `java-sim/reports/balance/` markdown-файлами.

### Смена свода правил

Свод — это версия правил, файл в `simulator/data/rulesets/`. Стенды принимают
его идентификатор первым аргументом. Значение по умолчанию прописано в
`GameConfig.DEFAULT_RULESET`.

Правило проекта: **версии контента неизменяемы.** Меняете правило — делаете новую
версию, а не правите старую. Иначе вчерашние замеры перестают что-либо значить.

## 3. Обучение и тесты — это РАЗНЫЕ запуски

Путать их нельзя, и я сам однажды спутал.

| | обучение | замер |
|---|---|---|
| чем | `SelfPlayTrainer` | `MatchLab`, `CardLab`, `Arena` |
| веса | меняются по ходу | заморожены, читаются с диска |
| что даёт | новые геномы на диск | числа про игру |
| можно ли сравнивать числа между линиями | **нет** | да |

Числа обучения («планка отложенной проверки») сравнивать между характерами
**нельзя**: у воителя другая формула цели, туда входят убийства и найм, поэтому
его 97.9 против 79 у остальных не означает, что он сильнее. Сравнивать можно
только за одним столом, очками и победами.

## 4. Грабли, на которые я уже наступил

Каждая из них стоила мне неверного вывода. Все пойманы измерением, ни одна —
рассуждением.

**Эло врёт на малых числах.** Бот, обыгравший всех соперников, оказался в лиге
последним. Инкрементальный рейтинг зависит от порядка партий. Заменено на подгонку
Брэдли–Терри плюс таблица «кто кого» — она и есть основание для решений.

**Проклятие оптимизатора.** Если выбирать лучшего из двадцати по шумному замеру,
победит тот, кому повезло. Лечится общими случайными числами (все варианты играют
на одних и тех же сидах) и отложенной проверкой на партиях, которых отбор не видел.

**Больше думает — меньше себе верит.** У просчёта доверие к собранной статистике
делилось на корень из числа наблюдений вместо `n/(n+2)`. Бот с большим бюджетом
играл хуже бота с малым. Поймано только лигой.

**Обрывать партию по очкам нечестно.** Если доигрывать не до конца, а до
горизонта, и судить по очкам, бот считает, что бросить армию посреди поля — не
страшно. Нужен судья с позиционной частью (`Lookahead.horizonScore`), иначе
просчёт учит трусости. Изолированный выигрыш от правки: 59% против 41%.

**Контрольный образец обязателен.** В каждом замере должна быть линия, которая
заведомо не должна выиграть. Если она выигрывает — сломан замер, а не игра.

**Ключи телеметрии.** Найм пишется как `units`, а не `units_made`. Я прочитал не
тот ключ и получил «найма ноль у всех». Если в замере строгий ноль — сначала
проверьте ключ, потом делайте выводы.

**Мёртвая пассивка невозможна по построению — и это надо беречь.** У каждой
способности арсенала объявлена точка правил, и есть тест, который валится, если
точку никто не спрашивает. Не отключайте его: карта, которую движок не спрашивает,
выглядит работающей и не делает ничего.

## 5. Что я знаю про саму игру (это важнее ботов)

Главный вывод всей работы, и он не про ботов:

> **Боты не воюют не потому, что глупые, а потому что война не окупается.**

Измерено на ваших раскладках, по 200 партий на состав, свод 1.7.1:

- партии кончаются на **6.0–6.4 раунда**, до восьмого почти никто не доживает;
- в **54–65%** случаев партию заканчивает **последний тайл зарождения**, то есть
  добыча, а не что-либо иное;
- **военная победа — около нуля** во всех двенадцати составах, включая стол из
  четырёх воителей;
- супер-задание — 0–3%.

Отбор честно находит то, что выигрывает. Пока партию решает добыча за шесть
раундов, любое обучение будет вытачивать строителя. Если обучить их воевать
насильно — они начнут проигрывать, и следующее поколение вылечит это обратно.

**Отсюда правило: сначала правила, потом боты.** Хотите 20% военных побед —
менять надо не бота, а то, за сколько раундов выгребается поле, и насколько
дорого стоит осада. Бот — это измерительный прибор, который честно показывает,
что в игре выгодно.

Разница между характерами при этом настоящая: стол воителей даёт 1.87
уничтожения на игрока, стол хаоса — 0.74, стол мирных — 1.15. Просто эта разница
не решает партию.

## 6. Про настоящие нейросети

Коротко: **да, это возможно, и это не требует ни меня, ни оплаты, ни интернета.**
Обучение нейросети — обычный локальный счёт на вашей машине. Но прежде чем
браться, стоит понимать, что вы за это получите и чего не получите.

### Что у вас уже есть

Геном — это уже обучаемая модель, которая живёт файлом и улучшается каждой
партией. Разница с нейросетью не в «учится / не учится», а в том, **какие
закономерности модель способна выразить**. Тридцать весов складываются линейно:
«келемий столько-то, убийство столько-то». Нейросеть может выразить «убийство
ценно, только если у противника осталось одно здание и идёт шестой раунд» — то,
что весами не записывается.

### Почему я снёс прежнюю нейро-ветку

Она была: PyTorch обучал, экспортировал в ONNX, Java играла. Снёс не потому, что
подход плох, а потому что **та ветка не выигрывала**: она проигрывала обычному
геному с просчётом, а поддерживать приходилось второй язык, второй набор
зависимостей и хрупкий формат обмена. Держать неработающее — хуже, чем не иметь.

### Честный порядок приоритетов

Если цель — «боты умнее», то по измеренной отдаче:

1. **Просчёт вперёд** — уже даёт 69% перевеса. Его настройка (ширина, горизонт,
   бюджет) не исчерпана.
2. **Правила игры** — пока партия решается добычей за шесть раундов, потолок
   осмысленности бота низкий независимо от модели.
3. **Веса** — вышли на плато: за 26 поколений чемпион сменился 15 раз против 45
   удержаний. Дальше выжимается мало.
4. **Нейросеть** — последняя по отдаче и первая по трудозатратам.

Если же цель — «хочу, чтобы каждая партия делала их умнее и это лежало файлом
модели», то это **уже так**, только файл маленький. Ощущение «настоящести» даст
не смена модели, а объём: обучать не на 200 тысячах партий, а непрерывно.

### Если всё же делать — как

Путь, который я считаю правильным, и он не требует Python:

1. **Начните с оценщика, а не с политики.** Пусть сеть предсказывает не «какой
   ход», а «чем кончится партия из этого положения». Такую сеть можно обучать на
   уже сыгранных партиях: положение → кто в итоге выиграл. Данные вы производите
   бесплатно, миллионами.
2. **Скармливайте её просчёту вместо судьи горизонта.** Это самая дешёвая
   пересадка: `Lookahead.horizonScore` заменяется вызовом сети, всё остальное
   остаётся. И сразу измеримо — тот же стенд, тот же контрольный образец.
3. **Обучение — на Java, без второго языка.** Небольшая полносвязная сеть
   (вход — сотня-другая чисел о положении, два слоя, выход — одно число)
   обучается обратным распространением в пару сотен строк. Второй язык и формат
   обмена — это ровно то, что убило прошлую попытку.
4. **Признаки положения важнее устройства сети.** Что подать на вход — келемий,
   очки, войска по родам, расстояния до чужого ЦУ, раунд — решает больше, чем
   число слоёв. Начните с тех величин, которые уже считает оценщик.
5. **Мерьте как всё остальное.** Новая сеть выходит в лигу против старого генома
   с просчётом. Не выиграла — не внедряем, сколько бы труда ни стоила. Это
   правило спасло меня от внедрения трёх «улучшений», которые не работали.

Чего ждать: на играх такого рода сеть-оценщик обычно даёт заметный прирост, но
**после** того, как исчерпан просчёт, и **только** если данных много. Это работа
не на вечер.

## 7. Если помощник другой

Что ему обязательно сказать в первые же минуты, иначе он наделает того же, что и я:

- СВОД правил и движок — **два равноправных источника правды**, менять только
  вместе. Всё остальное ниже рангом.
- Версии контента неизменяемы, новая настройка — новая версия.
- Тестировать только на ваших раскладках (папка `new`), встроенные поля примерно
  в полтора раза мирнее и врут в сторону оптимизма.
- Русские пути — только через PowerShell.
- Отчёты писать, только если попросили. Я на этом обжёгся: работа — это код и
  числа, а не документы о работе.
- Никогда не докладывать о сделанном, пока оно не сделано и не проверено. Я
  однажды сказал «откатил», не откатив.

## 8. Куда смотреть в коде

С 14.08.2026 пути начинаются с МОДУЛЯ (`engine/`, `bots/` или `gui/`), внутри —
как раньше (`src/main/java/kelium/...`), путь ниже сокращён без этой части.

| что | модуль | где |
|---|---|---|
| выбор бота, точки выбора | bots | `kelium/agents/StrategicAgent.java` |
| просчёт вперёд | bots | `kelium/agents/SearchAgent.java`, `Lookahead.java` |
| веса и профили характеров | bots | `kelium/agents/Genome.java` |
| цель отбора | bots | `kelium/agents/Fitness.java` |
| обучение | bots | `kelium/agents/SelfPlayTrainer.java` |
| список ботов (один на всё приложение) | bots | `kelium/agents/BotCatalog.java` |
| лига и таблица «кто кого» | bots | `kelium/agents/Arena.java` |
| стенд составов | bots | `kelium/MatchLab.java` |
| раннер (окно прогонов и обучения) | gui | `kelium/gui/RunnerGui.java` |
| стенд отдельных карт | bots | `kelium/CardLab.java` |
| способности арсенала | engine | `kelium/engine/ability/` |
| где что лежит на диске | engine | `kelium/dataio/Locations.java` |
