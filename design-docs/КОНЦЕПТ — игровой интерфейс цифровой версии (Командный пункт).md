# КОНЦЕПТ — игровой интерфейс цифровой версии («Командный пункт»)

**Статус:** концепт на утверждение дизайнеру. Код по нему не пишется, пока макеты
и решения ниже не согласованы.

**Основания:** два исследования 24.08.2026 — (а) анатомия игры: стол глазами
игрока по СВОДу + полный перечень точек решения движка (~85 видов `kind` плюс
семейство `ability:*`); (б) референсный анализ интерфейсов Hearthstone,
C&C/StarCraft II, Civilization V/VI, Into the Breach, цифровых Root/Terraforming
Mars/Scythe, Advance Wars/Wargroove, XCOM/Slay the Spire.

**Макеты:** `design-docs/КОНЦЕПТ — макеты интерфейса.html` (четыре экрана в
палитре Theme и шрифте Tektur; открывается любым браузером).

---

## 1. Принципы

1. **Поле — якорь.** Центр экрана всегда занят полем (его рисует существующий
   `FieldView`). Наука, рынок, чужие планшеты, журнал — выезжающие панели ПОВЕРХ,
   не вкладки и не отдельные экраны. Поле не сжимается ниже FIELD_MIN.
2. **Обратимое — мгновенно, необратимое — через крупное «да».** Стройка, Добыча,
   Манёвр, Смена энергии, Сборка играются без подтверждений и откатываются по
   клику. Бой и Рынок — одно крупное подтверждение с предпросмотром последствий.
   Асимметрия сама учит игрока, что опасно.
3. **Всё в один клик или наведение.** Полный текст карты — по наведению на
   миниатюру; слагаемые любого счётчика — в подсказке; чужой планшет — в ящике.
   Никакой факт партии не дальше одного действия мышью.
4. **Выбираешь на поле, а не в списке.** Гекс, сектора, цель атаки — кликом по
   самому полю с подсветкой легального. Кнопки — только для именованных
   вариантов (действие, трек, ставка).
5. **Ничего не телепортируется.** Чужой ход проигрывается шаг за шагом с
   подсветкой места события и кнопкой «пропустить»; каждое событие дублируется
   строкой ленты.
6. **Честный экран.** Скрытая информация чужих мест не появляется на экране
   никогда; между людьми — шторка передачи устройства с явным «это я».

## 2. Главный экран (макет «Экран 1»)

```
┌──────────────────────────────────────────────────────────────┐
│ ПОЛОСА ХОДА: раунд·круг · ВАШ ХОД/кто ходит · ресурсы + ПО    │
├──┬───────────────────────────────────────────┬───────────────┤
│ Я│                                            │ ШАГИ ХОДА     │
│ Щ│              ПОЛЕ (FieldView)              │ (цепочка с    │
│ И│    зум колесом · перетаскивание мышью      │  откатом и    │
│ К│    наведение на гекс = плашка секторов     │  замками)     │
│ И│                                            ├───────────────┤
│  │                                            │ ЛЕНТА ПАРТИИ  │
├──┴───────────────────────────────────────────┴───────────────┤
│ ТРИ РУКИ (миниатюры с hover-увеличением) · ПАНЕЛЬ ДЕЙСТВИЙ    │
│ (8 действий + СПЕЦ, недоступные серые с причиной) · ЗАВЕРШИТЬ │
└──────────────────────────────────────────────────────────────┘
```

Содержимое зон и что переиспользуется:

| Зона | Содержимое | Откуда берётся |
|---|---|---|
| Полоса хода | раунд/круг, чей ход цветом места, ресурсы с потолками (`2/4`), ПО золотом | `PublicView`/снимок; полоса из HotSeatWindow дорабатывается |
| Поле | всё как в проигрывателе + подсветки выбора | `FieldView` (клик по гексу уже есть) |
| Ящики слева | **Наука/Рынок** = `BoardsPanel`; **Планшет** (свой и чужие по табам мест) = `BoardSheet`; **Карты/колоды** = `DecksPanel` (в честном режиме); **Журнал** = `Timeline`/лента | всё уже написано для replay2, ящик — обёртка |
| Шаги хода | по строке на сыгранное действие; ⟲ «сюда» = откат; замок = необратимое | новый компонент + стек снимков движка |
| Лента партии | строка на событие, точка цветом места, клик = подсветить гекс | события `onFrame` уже идут |
| Три руки | приказы/задания/арсенал миниатюрами; на миниатюре задания — прогресс (`2/3` из `Objective.progress()`); hover = полная карта | `CardReader`/`HelpCards` для текстов |
| Панель действий | все 8 действий видны всегда, недоступные серые с причиной в подсказке; ниже СПЕЦ-плитки | меню `action`/`spec_*` движка |
| Завершить ход | = `pass` верхнего меню; показывает остаток («1 действие и СПЕЦ»); если остались обязательные решения — говорит какие | `TurnContext` (нужно донести в снимок, см. §8) |

## 3. Каждой точке движка — своя интеракция

Семьи (полные перечни `kind` — в отчёте-анатомии, здесь правило):

| Семья | Интеракция | Виды (основные) |
|---|---|---|
| **A. Цель на поле** | клик по гексу/жетону с подсветкой легального; для стройки — призрак и сектора; для боя — стрелка | `build_hex` `build_facing` `move_hex` `tower_hex` `energy_hex` `move` `maneuver_unit` `combat_source` `combat_target` `combat_victim` `neutral_victim` `attack` `landing` `evacuate` `dmg` `heal_target` `energy_place` |
| **B. Карта из руки/стопки** | сама рука кликабельна: легальные карты приподняты, прочие пригашены | `reveal_order` `blind_discard` `tuck_*` `spec_objective(_burn)` `spec_arsenal_burn/install` `arsenal_replace` `arsenal_display` `keep/drop_objective` `super_pick` `start_objective_pick` `spec_symbol_reveal` |
| **C. Именованный вариант** | плитки/кнопки в контекстной панели | `action` `spec_*`-меню `mine` `assemble` `build/move/demolish_pick` `market_rate` `sci_track` `sci_exchange` `storage_side` `module_bag` `red/blue_slot` `energy_*` `shield_kind` `speed_kind` `convert_any` `exchange_row` `loot` `steal_*` `container_variant` `trophy_*` `mandate_*` + `ability:*` (вливаются в те же меню по `OptionSource`) |
| **D. Число/ставка** | степпер/пара кнопок в той же панели | `spec_mandate_containers` `spec_combat` (цена в БПР) |
| **E. Подтверждение** | крупная панель с предпросмотром — ТОЛЬКО для необратимого | `attack` (первый залп), `market_offer`, `pass` хода при неиспользованных обязательствах, `pay_power`, `order_trade` |

Правило «всё или ничего» действует и здесь: если движок подмешал в семью A
вариант не-гексового вида, решение целиком уходит в панель C.

## 4. Стройка (макет «Экран 2»)

1. Плитка «Стройка» → меню зданий (семья C, с ценами; недоступные серые с
   причиной).
2. Выбрано здание → за курсором ездит **призрак** (полупрозрачный силуэт цвета
   игрока, ~42% альфы). Легальные гексы (список даёт движок — `build_hex`)
   обведены акцентом; на нелегальном под курсором призрак серо-красный с
   причиной («сектора заняты»).
3. На гексе под курсором подсвечены **сектора** дуги: зелёные — встанет,
   красный — конфликт. **Колесо мыши / Q-E вращают дугу** между вариантами
   движка (`build_facing`). Рядом чипы последствий соседства («стенкой к жиле»).
4. Клик — поставить. Никаких подтверждений: стройка обратима, она появляется в
   «Шагах хода» со стрелкой отката. Esc — отменить режим.

Тот же приём (без секторов) — перенос здания, вышка, энергия, манёвр
(двухслойная подсветка дальности как в Wargroove: зона хода + зона атаки).

## 5. Ход как цепочка шагов с откатом «до точки»

- Каждое **сыгранное** действие — строка в «Шагах хода». Клик «⟲ сюда» на любой
  обратимой строке откатывает партию к моменту ПЕРЕД этим действием (и всеми
  после него).
- Плюмбинг уже есть (`GameState.restoreFrom` + `UndoableAgent`), расширение —
  **стек** снимков вместо одного (снимок на входе в каждое безопасное действие).
- **Замки (необратимое):** вскрытие приказа, Бой (первый залп виден всем сразу —
  `combat_hit` рассылается по ходу боя), Рынок (ячейка карты расходуется на весь
  стол), Наука (общие треки и призы очередности). После замка строки выше него
  «запекаются» — откат к ним недоступен, и игрок это ВИДИТ заранее: панель
  подтверждения пишет «после этого откат шагов 2–4 станет недоступен».
- Известный компромисс: кадры записи об отменённых попытках остаются в журнале
  партии как след (для дизайнера это даже ценно — видно, что игрок передумал);
  живой экран после отката перерисовывается немедленно, не дожидаясь событий.

## 6. Бой (макет «Экран 3»)

1. Плитка «Бой» (или СПЕЦ-бой) → клик по своему жетону-источнику
   (`combat_source`, поле гасится на ~55%, легальные источники подняты).
2. Клик по цели (`combat_target`) — между ними стрелка.
3. **Панель подтверждения с предпросмотром:** урон и остаток прочности цели,
   расход БПР, откроется ли вторая атака, будет ли ответка. Красная кнопка
   прямо называет цену: «откат шагов N–M станет недоступен».
4. Дальше залпы (`attack`, цикл до паса) — каждый с мини-предпросмотром, но уже
   без крупного диалога: необратимость наступила на первом залпе.
5. **Ответный бой** — см. §7: решает обороняющийся.

## 7. Вне своего хода (находка анатомии — этого не было в прежних планах)

Движок спрашивает игрока и вне его хода, и hot-seat обязан это обслужить:

- **Ответный бой**: полный цикл `combat_source/target/attack` играет
  ОБОРОНЯЮЩИЙСЯ. Если это человек — шторка «Игрок N, на вас напали — ваш
  ответ» посреди чужого хода, с тем же интерфейсом боя; если бот — проигрывается
  как обычный ход бота.
- **Одновременное вскрытие приказов** (все места разом): в hot-seat — по очереди
  за шторкой («Игрок N, выберите карту круга», рука видна только ему), вскрытие
  показывается всем после последнего.
- **«Слепой» сброс** — на самом деле выбор (движок: `blind_discard_choice`),
  тоже за шторкой по очереди.
- **Смена модулей в Обновление, задержка трофея в Возврат** (`trophy_hold`),
  **реакции карт** — короткие решения, та же шторка с одним вопросом.

Шторка (макет «Экран 4») всегда двухступенчатая: гашение → «Я — Игрок N» →
рука открывается. На шторке — открытое резюме случившегося с прошлого раза.

## 8. Предпосылки в движке/данных (до или вместе с реализацией)

Честный живой экран сегодня НЕ может показать всё, что игрок видит за столом.
Дыры `PublicView`/снимка (из анатомии):

1. витрина арсенала `arsenalDisplay` (открыта всем — в PublicView нет);
2. размеры колод и верх сбросов (за столом видно число карт);
3. подложенные карты-символы `tucked` — нет нигде, даже факта;
4. `mandateArsenalCard/Containers` — есть в Player, нет в PublicView;
5. жетоны щита `shieldedKinds` — лежат открыто, в снимок не пишутся;
6. задержанные трофеи `destroyedOnCards` не отделены от обычных;
7. половинки модулей red/blueHalves не в PublicView.Seat;
8. контекст хода (сыграно/осталось действий, остаток СПЕЦ) живёт только в
   `TurnContext` — для полосы хода и кнопки «Завершить» его надо доносить.

Плюс: стек снимков в `UndoableAgent` (сейчас один); очередь-пейсер кадров для
хода бота; «первый игрок» и подложенные символы не рисует ни одна панель.

## 9. Что НЕ входит в первую версию

- Анимация переездов жетонов (пульса-подсветки и пошагового проигрывания
  достаточно; переезды — полировка).
- Особые интерфейсы под каждую `ability:*` (играются родными меню семей B/C).
- Перетаскивание карт мышью (drag-and-drop) — клик по приподнятой карте
  покрывает те же решения дешевле.
- Сетевой клиент этого экрана (архитектура готова — `InteractiveAgent` тот же,
  но веб/удалёнка — отдельный заказ).
- Переделка витрин рынка/науки сверх существующего `BoardsPanel`.

## 10. Этапы реализации (после утверждения концепта)

1. **Каркас экрана**: полоса хода, ящики с готовыми панелями (BoardsPanel,
   BoardSheet, Timeline), лента; вкладка-таб «Наука и рынок» уходит.
2. **Дыры данных** (§8, пп. 1–8) — PublicView/снимок/TurnContext.
3. **Руки как карты** с hover-увеличением и кликабельностью (семья B).
4. **Стройка**: призрак + сектора + вращение дуги (`build_facing`).
5. **Шаги хода**: стек снимков, откат «до точки», замки.
6. **Бой**: жест + подтверждение с предпросмотром; ответный бой через шторку.
7. **Шторки hot-seat**: передача устройства, одновременные фазы, короткие
   вне-ходовые решения.
8. **Пейсинг бота**: очередь кадров, пульс, «пропустить», скорость в настройках.

Каждый этап — играбельное состояние; порядок 1→2→3 даёт наибольший видимый
скачок при наименьшем риске.

## 11. Открытые вопросы дизайнеру

1. **Наука и Рынок в замках.** Предложено: оба необратимы (общие треки/ячейки).
   Согласен, или Науку без обмена трофеев считать обратимой?
2. **Вскрытие приказов в hot-seat**: строго за шторкой по очереди (честно, но
   медленно) или упрощённо «выбирает только тот, у кого устройство, остальные
   уже выбрали раньше»? Предложено: за шторкой.
3. **Ответный бой человека против человека**: шторка посреди чужого хода — ок?
4. Название концепта «Командный пункт» — принимается?

## Приложение. Попутные находки (не про GUI)

Анатомия зафиксировала расхождения markdown-СВОДа (ред. 07.08) с действующим
сводом 1.24.0/движком: боевая модель (ОСН/ВТР против «двух атак»), «слепой»
сброс (на деле выбор), лечение в Обновление (0 против «по кубику»), открытие
контейнера (СПЕЦ против свободного), манёвр (бесплатен против «конкурирует за
СПЕЦ [ТЕСТ]»), повторяемость печатных курсов рынка/науки, супер задания 3.0
против описания 2.0. Это к задаче синхронизации СВОДа, не к интерфейсу —
перечень в отчёте-анатомии сессии 24.08.2026.
