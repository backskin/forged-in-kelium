# План — доделать сетевую игру (21.10.2026)

Что уже есть и чего не хватает, чтобы в меню запуска перестала быть серой
плитка «По сети».

## Что есть сегодня

* **Авторитетный сервер.** `gui/net/GameServer` + `gui/net/Lobby`: стол
  создаётся, места раздаются (свободно / бот / человек), партия играется НА
  СЕРВЕРЕ, подключённому клиенту уходит `PublicView` и список вариантов, обратно
  приходит номер выбранного.
* **Консольный сетевой клиент** `gui/net/NetHotSeatCli` — доказательство, что
  тот же клиент играет по сети.
* **`PublicView`** — вид стола от лица одного места, уже с правильной границей
  закрытого: чужие руки приказов, заданий и арсенала закрыты, контейнеры —
  числом, слепой сброс рубашкой вверх.
* **Окно партии** `HotSeatWindow` — рисует стол НЕ из `GameState`, а из кадров
  записи (`ReplayRecord.Frame`, поле `snapshot`); живое состояние нужно ему
  всего в трёх местах: прогресс задания в подсказке, тег процента и запись
  кадра отката.
* **Воспроизводимость** — `GameSave` и `MoveLog`: партия = настройки + лента
  номеров выбранных опций.

## Чего нет

1. **Экрана лобби** — плитка «По сети» в меню отключена и честно говорит об этом.
2. **Сетевого окна партии**: окно сейчас само поднимает движок
   (`Setup.buildGame` в своём потоке). Клиенту движок поднимать нельзя — он
   должен рисовать то, что прислал сервер.
3. **Цензуры кадра**: кадр записи содержит ВСЁ (журнал по заказу пишет и
   закрытые руки). Клиенту нужен кадр, обрезанный по тому же правилу, что
   `PublicView`.

## Почему не «лента решений на всех клиентов»

Соблазнительный короткий путь: раздать всем настройки стола и гонять по сети
только номера решений — каждый клиент крутит свою копию движка, как при
загрузке сохранения. Это отвергается: у каждого клиента в памяти оказался бы
весь стол целиком, включая чужие руки, а заказ на цифровую версию (§4.4) прямо
требует обратного — «каждый клиент видит ТОЛЬКО то, что положено по правилам»,
и сервер остаётся единственным источником истины.

## Порядок работ

1. **Цензура кадра по месту.** Функция «кадр записи → кадр для места N»,
   режущая по той же границе, что `PublicView`. Сторож: тест, который на партии
   из нескольких ходов проверяет, что в обрезанном кадре нет ни одной чужой
   закрытой карты.
2. **Сервер раздаёт кадры.** `Lobby` уже ведёт партию; к существующей рассылке
   `PublicView` добавляется поток обрезанных кадров и прогресс заданий своего
   места (его клиент сам посчитать не может — для этого нужно состояние).
3. **Окно партии умеет две подачи.** Из `HotSeatWindow` выделяется источник:
   «местный движок» (как сейчас) либо «сетевая подача» — кадры и варианты
   приходят из сокета, выбор уходит обратно. Рисование, ящики, лента шагов и
   подсказки не трогаются вовсе.
4. **Экран лобби.** В меню запуска: «Поднять стол» (порт, число игроков, кто на
   каких местах) и «Подключиться» (адрес, порт, выбор свободного места). Старт
   у хозяина стола; у всех открывается окно партии.
5. **Обрыв связи.** Сервер ждёт возвращения того же места с разумным
   таймаутом; клиент при переподключении получает кадр целиком, а не разницу.

## Что это даёт

Hot-seat остаётся ровно таким, как сейчас (тот же код, «местная подача»), а
сетевая игра получает тот же интерфейс без второй отрисовки и без второго
движка.
