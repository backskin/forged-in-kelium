# СЕТЬ — архитектура сетевой игры (26.09.2026)

Для Влада и для следующего разработчика. Коротко: что выбрано, почему, как
друг ставит игру и садится за стол, какие экраны, что уже сделано в коде и что
дальше. Каркас лежит в `gui/src/main/java/kelium/gui/net/` (ветка `сеть-каркас`).

---

## 1. Модель: хост держит партию, остальные — только свои глаза

**Два пути**, оба опираются на то, что движок детерминирован (сид + лента
номеров выбранных вариантов = ровно та же партия):

| | Лок-степ по ленте решений | Авторитетный хост |
|---|---|---|
| Как | У каждого свой движок, сид общий, по сети летят только номера вариантов | Движок только у хоста; игрок получает СВОЙ вид стола и вопросы, отвечает номером |
| Трафик | Крошечный (одно число на решение) | Больше: кадры стола (десятки КБ на ход, сжимается) |
| Скрытое | **Провал.** С сидом у клиента вся колода и все руки: достаточно запустить движок у себя или заглянуть в память | Клиент физически не получает чужих рук, порядка колод и сида |
| Честность | Клиент может подсмотреть всё | Подсмотреть может только хост (для игры с друзьями приемлемо) |
| Рассинхрон | Любая разница в версии = тихо разные партии | Невозможен: партия одна |

**Выбран авторитетный хост.** Лок-степ ломается о главное правило игры —
руки заданий, приказов и арсенала видит только владелец. Детерминизм нам всё
равно пригождается: лента решений у хоста — это сохранение, откат и
переподключение (см. §5).

Главные правила хоста:
- **Сид клиентам не отдаётся до конца партии.** Сид + свод = порядок всех колод.
  В записи, которая уходит клиенту, сид обнулён; по окончании партии хост шлёт
  сид и ленту — у каждого остаётся полный журнал.
- **Клиент присылает только номер варианта** из списка, который ему прислал хост
  (`InteractiveAgent.submitIndex` уже проверяет диапазон). Любые другие данные
  клиента хост не читает.
- **Одна точка вырезания скрытого** — `net/Redact.java`: из каждого кадра для
  места N убираются руки других мест (`ordHand`, `objHand`, `arsHand`, отложенный
  приказ, закрытые подложенные карты), содержимое колод заменяется рубашками
  (число сохраняется — толщина колоды видна всем), мысли ботов выбрасываются,
  строки ленты о закрытом («получил задание «…»», «отложил «…»») переписываются
  без названия карты.

## 2. Где живёт хост и как найти друг друга

Хост — **процесс игрока, создавшего стол** (свой сервер не нужен). Он же играет
своё место в обычном окне партии.

Как соединиться — по ступеням, от простого к правильному:

1. **Прямое подключение IP:порт** (сделано). Локальная сеть — сразу. Через
   интернет без проброса портов — **виртуальная локалка**: Radmin VPN,
   ZeroTier или Tailscale (бесплатно, ставится за минуту, даёт «адрес в
   локалке» вида 26.x.x.x / 100.x.x.x). Это путь для первых партий с друзьями
   на этой неделе. Проброс порта на роутере тоже работает, но его никто не
   умеет.
2. **Код комнаты через ретранслятор** (следующий шаг). Маленький сервер на
   дешёвом хостинге (VPS за 200–300 ₽/мес или бесплатный уровень fly.io /
   Render): и хост, и игроки подключаются к нему ИСХОДЯЩИМ соединением
   (WebSocket по 443 — проходит через любой NAT и корпоративные сети).
   Ретранслятор знает только «комната ABC123 → вот эти соединения» и
   пересылает строки, партии он не видит. Протокол тот же самый — строки
   JSON, меняется только транспорт (`Wire` поверх WebSocket вместо сокета;
   в JDK есть `java.net.http.WebSocket` для клиента, сервер-ретранслятор —
   сто строк на чём угодно). Код комнаты — 6 знаков без похожих букв (как в
   старом `GameServer.randomId`).
3. **Выделенный авторитетный сервер** (потом, если понадобится честность
   против хоста или партии «без того, кто создал»). Прототип уже лежит в
   `net/GameServer` + `Lobby` (заказ §4.4): движок на сервере, коды лобби.
   Когда дойдёт — хост-логика переносится туда без смены протокола.

UPnP (автопроброс порта) не делаем: работает на половине роутеров, и
отлаживать его у друзей по телефону — хуже, чем поставить Radmin.

## 3. Протокол

Транспорт: TCP, **одна строка = один объект JSON** (UTF-8), JSON — наш
`kelium.report.Json`. Поле `t` — тип сообщения. Версия протокола
`NetProtocol.VERSION` (сейчас 2: отмена клиентом, пауза, закрытие хостом).

**Вход и лобби**

| → хосту | ← от хоста |
|---|---|
| `hello {proto, app, content, name, token?}` | `welcome {seat, token, lobby}` или `reject {reason}` |
| `seat {seat}` — пересесть | `lobby {seats:[{seat, kind, name, color, ready, online}], table:{players, ruleset, map}, canStart}` — при любом изменении |
| `ready {ready}` | |
| `chat {text}` | `chat {from, text}` |
| `bye` | |
| (хост у себя) места: бот/открыто, «Начать» | `start {seat, players, names}` |

`content` — отпечаток правил и карт (`ContentHash`: SHA-256 по `data/rulesets`,
`data/cards`, `data/boards`, `data/modules`, `data/blocks`, `data/components`;
раскладки полей не входят — поле хост присылает в шапке записи). Не совпал — отказ со словами «у вас другая версия правил —
обновите игру». Партию считает хост, так что при расхождении партия не
сломалась бы, но у друга были бы не те тексты карт — лучше не пускать.
`proto` не совпал — то же.

**Партия**

| ← от хоста | → хосту |
|---|---|
| `record {reset, from, chunk}` — новые кадры записи партии (уже вырезанные под это место); `reset` — вся запись заново с шапкой (поле, места, цвета, имена карт): после входа, переподключения, отката хоста | `resync` — попросить всю запись (кусок не состыковался) |
| `decide {seq, kind, prompt, options:[{i, kind, label, sub, hex?}], view}` — вопрос этому месту; `hex` — вариант выбирается щелчком по гексу; `view` — `PublicView` своими глазами | `answer {seq, i}` |
| `over {winner, condition, seed, moves}` — конец, сид и лента открываются | |
| `decide` несёт ещё `undo` — сколько своих шагов можно отменить, и `facing {hex, variants, ghost}` для выбора секторов на гексе (поворот здания, центра, сектор войска) | `undo {seq, all}` — отменить своё решение: шаг назад или к началу хода |
| `pause {seat, name, waiting}` — игрок вышел, партия стоит; `resume {seat, how}` — вернулся (`back`) или место боту (`bot`); `closed` — хост закрыл партию | |
| `error {text}` | |

`seq` — номер вопроса этому месту; ответ с чужим `seq` отбрасывается (так не
бывает двойного ответа после переподключения). Отдельного сообщения «ходит
такой-то» нет: чей ход, клиент читает из последнего кадра (`snapshot.active`).
Кадры идут пачками не чаще раза в 150 мс, и обязательно перед каждым вопросом.

**Откат в сети (решение Влада 26.09.2026, сделано).** Каждый отменяет СВОИ
решения, как за горячим стулом (в своём круге), но не глубже первого чужого
решения после них: как только в ленте встало решение другого места — защита,
реакция, общий вопрос, — всё до него запеклось (`NetSeats.undoTargets`, одно
правило для хоста и клиента). У хоста — прежние «Шаг назад» / «К началу хода» /
Ctrl+Z. У клиента — те же две кнопки и Ctrl+Z в окне партии: пока ему задан
вопрос, он шлёт `undo {seq, all}`; хост проверяет правило, откатывает партию
переигровкой ленты (окно хоста — своим откатом, `NetGame` — заново с
префиксом ленты), всем уходит запись заново и новый вопрос. Нечего отменять —
`error` и тот же вопрос.

## 4. Переподключение и сохранение

Сделано: токен, ожидание, досылка всей записи и висящего вопроса. План:
«отдать боту», сетевые сохранения, автосохранение хоста.

- При входе хост выдаёт месту **токен**. Связь оборвалась — место не
  освобождается, партия ждёт (для игры с друзьями таймеры не нужны). Клиент
  подключается снова с тем же токеном → `welcome` на своё место → `resync`
  (вся запись) и заново текущий `decide`, если он висел.
- **Отвал игрока (решение Влада 26.09.2026, сделано)** — партия встаёт на
  паузу (движок стоит на ближайшем кадре). У хоста поверх окна партии —
  затемнение и карточка «Игрок N (имя) вышел из игры» с тремя выходами:
  «Ждать игрока» (карточка остаётся с пометкой ожидания, можно передумать),
  «Заменить ботом» (место доигрывает бот `NetHost.STAND_IN_BOT` — через
  справочник ботов с тем же зерном места, что у окна партии; вернуться на
  место игрок уже не сможет), «Закрыть партию». У остальных — то же
  затемнение и «Игрок N вышел из игры. Ждём решения хоста», без кнопок.
  Вернулся игрок или место отдано боту — шторка у всех снимается. Хост закрыл
  партию (кнопкой, закрытием окна партии или окна лобби) — у игроков в том же
  окне «Хост закрыл партию» и «Выйти из игры».
- **Сохранение** — тот же `GameSave` у хоста: настройки + лента. Сетевые места
  уже пишутся как `net:<место>` (сейчас такое сохранение, открытое без сети,
  посадит на это место бота). Загрузка у хоста = снова лобби с теми же местами,
  друзья входят, лента доигрывается до места сохранения, игра идёт дальше.
- Упал сам хост — партия продолжается с его последнего сохранения
  (автосохранение хоста раз в ход — дешёво, лента маленькая).

## 5. Установка: как друг получает игру

Уже есть всё нужное: `make-exe.ps1` собирает папку `dist` (маленькие
exe-запускатели + `packs\*.pak`, Java внутри, ничего ставить не надо).

1. **Сейчас:** Влад архивирует `dist` в zip и кидает ссылку (Яндекс.Диск /
   Google Drive / GitHub Releases). Друг распаковывает куда угодно, запускает
   `Играть.exe`. Первый запуск распаковывает паки в `%LOCALAPPDATA%\Kelium`.
   Предупредить друга о двух окнах Windows: SmartScreen («Подробнее →
   Выполнить в любом случае» — exe не подписан) и брандмауэр у ХОСТА
   («Разрешить доступ» для Java — иначе к нему не подключиться).
2. **Автообновление (следующий шаг, дёшево):** у паков уже есть отпечатки
   (`packs.txt`). Запускатель при старте скачивает `packs.txt` по адресу
   (тот же хостинг / GitHub Releases), сравнивает отпечатки и докачивает
   только изменившиеся паки — обычно `code.pak` и `rules.pak`, это единицы
   МБ, картинки не трогаются. Тогда у всех одна версия, и отказ по `content`
   почти не случается.
3. **Приглашение ссылкой (потом):** запускатель регистрирует протокол
   `kelium://join/ABC123` — друг щёлкает ссылку в мессенджере, игра открывается
   сразу в лобби. До этого приглашение — просто текст «адрес 26.12.34.56:47100»
   или код комнаты, который копируется кнопкой.

## 6. Экраны

**«Штаб» → «По сети».** Плитка режима больше не заглушка: открывает окно
«Сетевой стол» в той же палитре стола (`Theme.applyTable`), крупные шрифты.

```
┌ СЕТЕВОЙ СТОЛ ──────────────────────────────────────────────────┐
│ Ваше имя  [ Влад            ]                                  │
│                                                                │
│ ┌ СОЗДАТЬ СТОЛ ─────────────┐   ┌ ВОЙТИ К ДРУГУ ─────────────┐ │
│ │ порт [47100]              │   │ адрес  [26.12.34.56:47100] │ │
│ │ (стол — как собран в Штабе│   │                            │ │
│ │  игроков, правила, поле)  │   │        [ Войти ]           │ │
│ │     [ Создать стол ]      │   │                            │ │
│ └───────────────────────────┘   └────────────────────────────┘ │
├────────────────────────────────────────────────────────────────┤
│ ЛОББИ   Адрес для друзей: 192.168.1.5:47100  [Скопировать]     │
│  ● Место 1  Влад (хост)          готов                         │
│  ● Место 2  Саша                 не готов   [Сесть сюда]       │
│  ○ Место 3  свободно             [Бот ▾] [Открыть]             │
│  ● Место 4  Бот · Стратег                                      │
│ ─ чат ─────────────────────────────────────────────────────── │
│  Саша: щас, чай налью                                          │
│  [ сообщение…                                   ] [Отправить]  │
│                         [ Готов ]   [ НАЧАТЬ ПАРТИЮ ] (хост)   │
└────────────────────────────────────────────────────────────────┘
```

- Имя запоминается (`AppSettings`).
- Хост выбирает стол в «Штабе» как обычно (игроки, правила, поле, цвета, сид);
  места, отданные там «живым», в лобби — открытые для друзей, боты — боты.
  Хост может любое открытое место отдать боту и обратно.
- «Начать» горит, когда все живые места заняты и все готовы; иначе подпись,
  чего не хватает («ждём: место 2 не готово»).
- Отказ входа — словами: «у Влада другая версия правил: обновите игру»,
  «стол полон», «партия уже идёт — войти можно только на своё место».

**В партии.** Шторки нет: у каждого свой экран. Когда ходит другой — полоса
хода пишет «Ход соперника: Саша» и все органы ввода серые, поле живёт кадрами
хода соперника. Нет связи с кем-то — пауза со шторкой (§4). Чат — в лобби и
в партии: у хоста и у клиента в левом нижнем углу поля кнопка «Чат»; новое
сообщение при свёрнутом чате зажигает кнопку и показывает текст в подписи. У клиента пропала связь с хостом — «переподключаемся…», сам
повторяет раз в пару секунд.

## 7. Что сделано в каркасе (ветка `сеть-каркас`)

Пакет `gui/src/main/java/kelium/gui/net/`:

- `NetProtocol`, `Wire` — строки JSON поверх сокета, версии, типы сообщений.
- `ContentHash` — отпечаток правил и карт.
- `Redact` — вырезание скрытого под место (одна точка).
- `NetHost` — стол в процессе хоста: приём подключений, сверка версий, места,
  токены, чат, «Начать», рассылка кадров; `RemoteAgent` — сетевое место для
  движка хоста (шлёт `decide`, ждёт `answer`, переживает обрыв).
- `NetClient` — клиент: вход, лобби, кадры, вопросы, ответы, переподключение
  по токену.
- `NetGame` — партия у хоста без окна (проверка; стол, за которым хост не
  играет). Стол собирается ровно как в окне партии.
- `NetSeats` — точка встраивания в окно партии хоста: места `net:N`. В
  `HotSeatWindow` шесть точечных строк: агент сетевого места, кадры сети,
  конец партии, имя места, откат только до чужого решения, без пауз «бота»
  на сетевых ходах. `kindLabel` и `GameRecorder.live` стали public,
  `ReplayRecord.fromJsonMap` — вход записи из разобранного JSON.
- `LobbyWindow` — окно «Сетевой стол» из «Штаба» (плитка «По сети» больше не
  заглушка); `NetClientWindow` — прототип окна партии у клиента: настоящее
  поле по присланным кадрам, своя рука и запасы, лента, вопрос кнопками
  (гексы — и щелчком по полю), «Ход соперника: …», сам переподключается.

Проверено:
- `NetLoopbackTest`: хост и клиент в одном процессе по localhost доигрывают
  партию (2 места, 8 раундов, ~400 кадров, ~180 решений клиента) с обрывом
  и переподключением посреди. Для каждого кадра и вопроса сверяется, что
  клиенту не ушло ни id, ни названия карт, закрытых от него в этот миг
  (руки соперника, отложенный приказ, закрытые подложенные, колоды), ни сида,
  ни мыслей ботов. Проверка сама ловит утечку: при выключенном вырезании руки
  или строки «получил задание «…»» тест падает. Лента сетевой партии
  совпадает с той же партией без сети.
- Прогон окнами: хост в настоящем окне партии, друг в `NetClientWindow`,
  партия до конца (8 раундов). Трафик к клиенту за партию ~6 МБ (кадры со
  снимками стола) — для локалки и VPN терпимо, сжатие — в план.

## 8. Риски

1. **Окно клиента.** Окно партии (`HotSeatWindow`) рисует ИЗ `GameState`
   живого движка в том же процессе. У клиента движка нет — только кадры
   записи и вопросы. Правильный путь: отвязать окно от движка через
   «источник партии» (кадры + вопросы + ответ), которым станут и горячий стул,
   и сеть. Это большая правка окна, её надо делать вместе с основным
   разработчиком, не параллельно. Пока — прототип `NetClientWindow`.
2. **Утечки через текст.** Строки ленты и подписи вариантов пишутся для
   всевидящего журнала. Новое событие с названием закрытой карты в тексте
   протечёт, если его не внести в `Redact`. Сторожит тест (ищет названия и id
   чужих закрытых карт во всём, что пришло клиенту) — гонять его при каждом
   новом событии.
3. **Вес кадров.** Снимок стола — десятки КБ, за партию на двоих ~6 МБ
   клиенту. Хост уже шлёт пачками (≤ 7 раз в секунду); дальше — gzip строки
   (снимки жмутся в разы) или разница снимков.
4. **Хост может подсмотреть.** Принято для игры с друзьями; лечится
   выделенным сервером (§2 п.3).
5. **Версии.** Без автообновления друзья будут с разными сборками — отказ по
   `content` скажет об этом словами, но играть не даст.

   окна клиента.
2. Окно партии: «источник партии» вместо прямого `GameState`; клиент играет в
   настоящем окне (рука, стол, вопросы на поле). Откат по правилу §3.
3. Автообновление запускателя + приглашение текстом/кнопкой «скопировать».
4. Ретранслятор с кодом комнаты (WebSocket), `kelium://join/КОД`.
5. Сетевые сохранения. («Отдать место боту», пауза, чат в партии, отмена клиентом — сделано.)
6. (по нужде) выделенный сервер.
