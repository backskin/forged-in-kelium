# Кристаллы Раздора — движок, боты и разбор партий

Java-часть проекта настольной игры: правила, симуляция партий, боты и приложения,
которыми пользуется дизайнер.

## Что здесь лежит, а что нет

Репозиторий самодостаточен: в нём всё, что нужно для разработки и запуска.

| Папка | Что внутри |
|---|---|
| `engine/`, `bots/`, `gui/` | исходники: движок, боты, приложения |
| `data/` | данные игры: правила, карты, планшеты, раскладки, текстуры, модели ботов |
| `rules/` | **копия** документов правил — читать, не редактировать (см. `rules/README.md`) |
| `icons/`, `launchers-macos-linux/` | значки приложений и запускалки |

**Снаружи остаётся производство настоящей игры**: макеты для печати, иллюстрации,
компоненты, исходники карт в графических редакторах. Им место в рабочей папке
дизайнера, а не в репозитории кода.

Каталог данных ищется сам (`GameConfig.resolveDataRoot`): `data/` в корне, а при
запуске из модуля — `../data`. Переопределить можно свойством `-Dkelium.data=…`.

Репозиторий сознательно живёт **вне облачной синхронизации**: клиент Яндекс.Диска
портил `.git` — оставлял копии-конфликты ссылок и не скачивал часть объектов, из-за
чего git переставал читать собственную историю.

## Приложения

| exe | что делает | главный класс |
|---|---|---|
| `KeliumReplay2` | разбор партии: поле по шагам, планшеты, итоги, справочник | `kelium.gui.replay2.Replay2Gui` |
| `KeliumConstructor` | конструктор раскладок поля (`.kmap`) | `kelium.gui.LayoutEditor` |
| `KeliumRunner` | прогоны симуляций пачками, отчёты | `kelium.gui.RunnerGui` |
| `KeliumHelp` | справочник отдельно: правила и все карты | `kelium.gui.replay2.HelpApp` |

## Что нужно поставить

- **JDK 21** (собрано на Temurin 21). В `PATH` должны быть `java`, `javac`,
  `jlink`, `jpackage` — последние два входят в JDK, но не в JRE.
- **Maven 3.9+**.
- Для сборки exe — Windows и `csc.exe` из .NET Framework 4
  (`C:\Windows\Microsoft.NET\Framework64\v4.0.30319\csc.exe`), он уже есть в
  системе. Им собирается крохотная программа-самораспаковщик.

## Сборка и запуск из исходников

```bash
mvn -o -q compile
```

`-o` — офлайн: все зависимости уже лежат в локальном репозитории, в сеть ходить
не нужно.

```bash
mvn -o test
```

Тесты (около трёхсот) проверяют правила, бой, энергию, раскладки и отрисовку.
Падение теста — это расхождение движка со СВОДом правил, а не «шум»: разбираться
надо с ним, а не с тестом.

Запустить приложение, не собирая exe:

```bash
mvn -o exec:java -Dexec.mainClass=kelium.gui.replay2.Replay2Gui
```

Полезные ключи запуска:

- `-Dkelium.data=<путь>` — где лежат данные игры (по умолчанию ищется
  `../simulator/data`);
- `-Dkelium.theme=light|dark` — открыть в нужной теме, не трогая запомненную
  настройку.

## Сборка exe

```powershell
powershell -ExecutionPolicy Bypass -File make-exe.ps1
```

Готовые файлы появятся в `dist\`. Каждый exe **самодостаточен**: внутри и
приложение, и урезанная Java-среда — ставить Java на машину не нужно. При первом
запуске файл распаковывается во временную папку, дальше стартует сразу.

Что делает скрипт:

1. `mvn -o -q package` — собирает jar приложения;
2. `jlink` — режет Java-среду до нужных модулей (`java.base`, `java.desktop`,
   `java.logging`, `java.management`, `jdk.unsupported`);
3. `jpackage --type app-image` — собирает образ приложения на каждый главный
   класс;
4. дописывает в `.cfg` путь к данным игры;
5. собирает `csc.exe` самораспаковщик и запаковывает в него образ;
6. кладёт результат в `dist\`.

Две вещи, на которых сборка спотыкается чаще всего:

- **Скрипт обязан быть сохранён в UTF-8 С BOM.** Без BOM PowerShell 5.1 читает
  его как ANSI и ломается на кириллице.
- **Запущенные приложения держат свои файлы.** Скрипт нарочно падает с понятным
  сообщением, если найдёт работающий процесс `Kelium*` — закройте их и повторите.
  По той же причине удаление старых exe идёт с повторами: свежий крупный файл
  часто ещё сканирует антивирус или синхронизирует Яндекс.Диск.

Ярлыки для тех же действий лежат рядом: `Пересобрать.bat`,
`Запустить-раннер.bat`, `Собрать-картинки-справочника.bat`.

## Как устроен код

```
kelium/core      незыблемое ядро: состояние, доски, ресурсы
kelium/rules     правила версии: чтение YAML, доступ по ключам
kelium/dataio    загрузка данных: наборы карт, конфигурация партии
kelium/engine    сама игра: подготовка, действия, бой, энергия, подсчёт очков
kelium/agents    боты
kelium/report    запись партии и общая отрисовка поля (Java2D и SVG)
kelium/gui       приложения: конструктор, раннер
kelium/gui/replay2  разбор партии 2.0
```

Три правила, которые здесь соблюдаются:

- **Ядро не знает про версии.** Всё версионируемое живёт в данных, а не в коде.
- **Отрисовка поля одна на всех.** `FieldPainter` рисует в абстрактный холст;
  приложение подставляет Java2D, отчёты — SVG. Поле на экране и в отчёте
  разойтись не могут.
- **Чего в записи нет — то так и подписано.** Приложение не додумывает данные:
  неизвестное показывается словами «не описано», а не выдуманным значением.

## Данные и версии

Версию правил и версии карточных наборов выбирает партия: правила называют свои
наборы в `content_versions`, а в настройке партии можно взять другую редакцию
заданий или арсенала, не меняя правил. Архив старых приложений — в `archive/`.
