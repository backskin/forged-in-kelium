# ПЛЕЙБУК — как быстро перенести правку компонентов в игру

Памятка для следующей сессии (составлена 25.09.2026). Дизайнер будет менять:
задания (обычные, начальные, супер), арсенал (обычный, начальный, супер),
изредка приказы, контейнеры и их награды, планшеты войск и хранилища (цены,
цели атак, производство, числа на жетонах). Здесь — где что лежит и в каком
порядке это переносить, чтобы не открывать проект с нуля.

## 0. Незыблемые правила

1. **Картинка — эталон.** Экспорт на Диске новее кода. Каждую карту читать
   ГЛАЗАМИ (Read по PNG, мелкое — увеличить PIL-кропом), не по расшифровке и
   не грепом. Сверять даты файлов экспорта: дизайнер дорисовывает.
2. **Карту называть полным печатным текстом** (условие, усиление, награды,
   верх), никогда не номером или id — ни в ответе, ни в вопросах.
3. **Свод и движок меняются вместе.** Правило = ключ в
   `data/rulesets/1.45.0.yaml` + код, который его читает + подпись ключа в
   `gui/.../replay2/RuleWords.java` (+ строка в `RulesBook.java`, если это
   текст справочника).
4. **Версии контента не редактируются** после выпуска: новая правка — новый
   файл (`objectives.1.20.0.yaml`, `boards.3.2.0.yaml`), в своде меняется
   только строка `content_versions.<набор>`. Свод правится на месте (версия
   свода поднимается только по решению дизайнера).
5. **Соседние чаты.** Перед работой — `ListAgents`; если кто-то busy в тех же
   файлах — написать ему, кто что берёт. Коммитить ТОЛЬКО свои файлы
   (`git add <путь>`), никогда `git add -A`: соседи держат незакоммиченное.
6. Java править Edit'ом; кириллица в путях Git Bash ломается — такие пути
   через PowerShell или Python-скрипт с `PYTHONIOENCODING=utf-8`.
7. Сборка: `mvn -o -q -pl engine,cards,bots,gui -am compile`. Тесты модуля gui
   гонять только с `-am` (иначе подхватится старый engine из ~/.m2):
   `mvn -o -pl gui -am test -Dtest=... -DfailIfNoTests=false -Dsurefire.failIfNoSpecifiedTests=false`.

## 2. Скрипты раскладки текстур (tools/)

Каждый скрипт держит таблицу «файл экспорта → имя в игре», прочитанную по
картинкам. Новый экспорт — поправить таблицу (если сменился порядок/число
файлов) и перезапустить. После — посмотреть результат глазами.

| Скрипт | Что пишет |
|---|---|
| `gen_card_art.py` | лица заданий, начальных, арсенала всех трёх видов → `data/textures/card/<колода>/<id>.png` |
| `gen_card_faces.py` | приказы, контейнеры, рубашки `deck_*`, памятки, рубашка рынка; `РЫНОК_ПЕЧАТЬ` — что напечатано на рынке |
| `gen_token_art.py` → `gen_token_zones.py` | жетоны по цветам, обороты, супер, нейтралы; затем разметка зон (сердца, ячейки энергии, гарнизон) |
| `gen_board_art.py` → `gen_anchors.py` | планшеты войск и хранилища, наука, рынок; затем якоря `board/anchors.yaml` (сам сверяет) |
| `gen_module_art.py` | жетоны модулей (красные, синие, ЦУ, хранилища) |
| `gen_super_objective_faces.py` | лица супер-заданий: текст условий из набора под плашками трёх шаблонов дизайнера, лист лиц в design-docs |
| `gen_hex_art.py` | тайлы зарождения (запретные — только если есть отдельные файлы) |
| `gen_block_art.py` | модули поля (блоки) с якорями и сверкой по data/blocks |

Имя лица = ТОЧНЫЙ id карты из каталога; игра находит его сама через
`Textures.cardFace(колода, id)`. Новая карта = новая строка таблицы.

## 3. Где правила карт в коде

| Колода | Источник правды (классы) | Каталог (выгрузка) | Ключ свода |
|---|---|---|---|
| задания + начальные | `cards/.../objectives/*` (`Задания*.java`, `НачальныеЗадания.java`, `СемействаЗаданий`) | `data/cards/objectives.<v>.yaml` ← `tools/собрать-задания-1-19-0.py` | `objectives` |
| супер-задания | движок: `СуперЗадания` (категории и звёзды разделов), `Scoring`, `Setup` | `super_objectives.<v>.yaml` (`categories` — печатный текст, `vp` — звёзды плашек) | `super_objectives` |
| арсенал + начальный | `cards/.../arsenal/Арсенал7.java`, способности `engine/.../ability/Arsenal7Abilities.java` | `arsenal.<v>.yaml` ← `kelium.ВыгрузкаАрсенала` (bots) | `arsenal` |
| супер-арсенал | `cards/.../superarsenal/СуперАрсенал3.java` | `super_arsenal.<v>.yaml` | `super_arsenal` |
| рынок | `cards/.../market/СделкиНаРынке3.java` | `market.<v>.yaml` | `market` |
| приказы | данные | `orders.<v>.yaml` | `orders` |
| контейнеры | `engine/.../PrintedContainers.java` + данные | `containers.<v>.yaml` | `containers` |

Порядок для правки колоды:
1. прочитать все картинки, составить таблицу «файл → id → было/стало» полным
   текстом;
2. поправить классы (новая механика — в движке по образцу соседних
   способностей; нечестно реализуемое — не выдумывать, спросить);
3. выгрузить новую версию каталога, в своде поменять `content_versions`;
4. разложить лица (`gen_card_art.py`/`gen_card_faces.py`);
5. `mvn test` по engine и cards, затем HotSeatUiClickTest (см. §6);
6. вопросы по неоднозначным иконкам — списком, каждую карту её текстом.

Если картинок меньше, чем карт (дизайнер не дорисовал), — пустые заготовки
не вводить; карта появится, когда дорисует: одна строка в таблице скрипта +
одна карта в классе.

## 4. Планшеты и фракции

Всё числовое — `data/boards/boards.<v>.yaml`:
- общие жетоны: `token_stats` (прочность войск и их трофеи, здания, добытчики
  и станции по уровням с трофеем на обороте);
- фракции: записи `troop_red/green/blue/yellow` — `attacks` (цель спец-атаки
  рода), `speeds`, `building_prices`, `production` (боеприпасы/войска за
  Снаряжение по зданию; ЦУ тоже здесь), `tokens` (прочность и ячейки,
  напечатанные на жетонах этого цвета);
- хранилище: `storage_A` (ячейки по уровням).
- какой цвет у какого места — `asymmetry.board_sides` свода.

Код: `TroopSide` (читает сторону), `Modules.assemblyOutput` (выход
Снаряжения с жетоном модуля), `Placement` (стройка), `CombatResolver` (цели).
Сверка печати с данными: числа сердец и ячеек на жетонах — глазами, обороты
(шестерни) — это трофеи.

## 5. Приложение — куда смотрит интерфейс

- окно партии: `gui/.../HotSeatWindow.java` (маршрут решений `routeOnField`,
  подписи видов `KIND_LABELS`), выбор на поле — `kp/FieldBubbles`, подписи
  вариантов — `kp/ChoiceWords`, стол игрока — `kp/PlayerTable`, раскрытые
  карты — `kp/CardSpread`, вскрытие — `kp/CardChoiceOverlay`;
- планшеты рисует `replay2/PrintedBoards` (зоны щелчка — `hits`);
- у нового вида решения движка: подпись в `KIND_LABELS`, перевод варианта в
  `ChoiceWords`, привязка к гексу/детали — `anchorOf`/`boardKeyOf`.
- пропорцию карты НЕ задавать числом — она берётся с картинки.

## 6. Проверка

- `HotSeatUiClickTest` — восемь столов до финала ТОЛЬКО через экран; падает с
  именем решения, если его нечем нажать. Гонять после любой правки правил.
- `HotSeatUndoTest`, `ReplayUndoDeterminismTest` — откат переигровкой.
- Снимок окна: `java -cp … kelium.gui.HotSeatShot <png> <вид решения> <пропуск> <сид> <ш> <в>`,
  `-Dshot.spread=objectives|arsenal|dump` — с раскрытой рукой. Смотреть снимок
  глазами после каждой правки интерфейса.
- В конце — `make-exe.ps1` (пересборка exe в dist/).
